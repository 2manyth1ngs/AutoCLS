# Gate v2 判据定义（**先于任何重评估结果写定**）

日期：2026-08-04 ｜ 状态：设计稿，写于跑数字之前（本文件的 git 历史可验证这一点）

> **本文件的存在就是防「为了凑够 100 而设计判据」的机制**：判据的每个环节与每个阈值
> 都必须在这里给出**独立于 13 个数据集重评估结果**的理由。写完这份文档之后才允许
> 跑重评估，并且**接受它给出的任何结果**——包括任务数比旧判据的 74 更低。

## 0. 为什么要换判据（不是为了让更多数据集通过）

`results/probe_sensitivity/REPORT.md`（commit 91eaba6）证明旧判据
（`autocls/snr_gate.py: decide`，SNR≥1 且 `pair_sign_stability`≥0.7）有两个**结构性**缺陷，
与阈值定在哪里无关：

1. **循环性**：`pair_sign_stability` = 「所有成对差值符号跨 seed 恒定」的比例。往探针
   集里放一条 R' 远低于其余的退化 CLS，就凭空造出一批**永远稳**的平凡成对，把比例
   整体抬高。实测 Pearson(退针集中退化 CLS 占比, 任务数闸) = **0.751**；93 个不含
   退化 CLS 的子集里最低给 gate=44；**去掉一条常规 CLS 反而让闸从 74 涨到 96**。
   探针 CLS 与 shared label CLS 是同一批（`configs/labels.yaml: route_a.n_shared_cls=10`
   = 探针目录前 10），因此这个循环性直接落在闸门结果上。
2. **口径不一致**：闸门的分母包含 δ 本就会丢弃的近平局对，而下游造 label
   （`autocls/labeling.py: make_pairs`）第一件事就是 `|R'_a−R'_b| < δ → 弃样`。
   闸门因此在一批**下游根本不会用到的配对**上做判决，同时误杀 NATOPS
   （δ 后 25/56 label、方向稳定 0.84）与放行 AWR（3/56）、CharacterTrajectories（0/56）。

**换判据的理由是这两条，不是「74 太低」。** 「闸不过」在旧判据下是稳健结论
（k≥8 时 637 个子集中 P(任务数≥100)=0.00），新判据完全可能给出更低的数——那也照报。

## 1. 判据：直接测下游真正需要的两个数

下游（阶段 2 造 label）对一个源数据集的唯一要求是：**它能产出多少条方向可靠的 label**。
Gate v2 就直接测这两个量，不再绕道 SNR / 全体成对符号稳定率。

### 1.1 测量口径（与真实造 label 逐字对齐）

对数据集 D 的每个任务 t、每个无序 CLS 对 (a, b)：

| 环节 | 口径 | 对齐对象 |
|---|---|---|
| label 的 R' 来源 | **canonical 单种子**（seed 0，`weight_seed/split_seed` 由 `run_seed_for` 派生） | 路线 A k=1，`scripts/2b_generate_labels_route_a.py` |
| 候选对 | 两侧 canonical R' 均有限 | `make_pairs`：任一方非有限 → 剔除 |
| δ 过滤 | `\|R'_a − R'_b\| < δ` → 弃样 | `make_pairs` 同一行 |
| label 方向 | `is_better(R'_a, R'_b, task_type)` | 铁律 8（禁止硬编码 `>`） |

### 1.2 指标 1 — 产量 Y(δ)

```
Y(δ) = (δ 过滤后存活的配对数) / (候选配对数)
```
候选配对数 = 每任务 C(10,2)=45 × 2 个任务 = **90/数据集**（本批缓存的 10 条 shared CLS）。

### 1.3 指标 2 — 方向正确率 A(δ)

```
A(δ) = (存活配对中，canonical 方向 == 多种子共识方向 的比例)
```

- **共识方向**：由 seed 1/2/3 的 R' 均值经 `is_better` 判定；三种子共识为平局
  （`is_better` 双向皆 False）时该对方向无定义，不计入分母（同
  `labeling.delta_decision_curve` 对 full 平局的处理）。
- **为什么这是无偏的**：canonical 缓存只有 seed 0，噪声缓存只有 seed 1/2/3，
  两者不重叠 —— label 不参与自己的共识投票（天然留一法）。且每个 seed 换的是
  `weight_seed` **和** `split_seed`，共识是**独立划分上的真实复现检验**，
  不只是权重初始化抖动。
- 这与探针 §2.2 的「标签正确率」是**同一个定义**：「用生产口径造 label（单种子 ΔR'，
  |ΔR'|≥δ 才保留），检验其方向是否等于多种子共识方向」。

### 1.4 判定

```
pass(D)  ⟺  ∃δ ∈ 网格：A(δ) ≥ 0.95  且  Y(δ) ≥ 1/3
δ*(D)    = 满足上式的最小 δ（Y 随 δ 单调降，故 δ* 处产量最高）
```
δ 网格：0.005 起步、步长 0.005 至 0.20（覆盖探针用过的 0.02/0.03/0.05/0.08）。

不通过再分两型（**只是失败原因的标注，不影响 pass/fail**）：
- `fail_noisy`：某些 δ 能达 A≥0.95，但那时 Y<1/3 —— 干净得起，但产量不够；
- `fail_unreliable`：**任何** δ 都达不到 A≥0.95 —— 方向本身就是噪声（PenDigits 模式）。

## 2. 每个阈值的独立理由

> 红线：阈值不得因为「这样能让 N 个数据集过」而选。以下两个数**全部继承自本项目
> 更早、为不同数据集做出的决定**，本会话没有新调任何数字。

### 2.1 A_floor = 0.95 — 继承自 δ 的标定判据本身

`configs/labels.yaml` 里 `delta_per_dataset` 的三个实测值是这样定出来的
（`results/route_a_probe/REPORT.md` §2.2，表头逐字：**「达 ≥95% 正确所需 δ」**）：

| 数据集 | 选定 δ | 该 δ 下的正确率 |
|---|---|---|
| SpokenArabicDigits | 0.03 | 96.1% |
| PhonemeSpectra | 0.05 | 98.5% |
| Cricket | 0.08 | 97.1% |

即 **δ 的定义就是「使 label 方向正确率达到 95% 的过滤强度」**。Gate v2 的 A_floor 只是
把这个既有定义原样搬来当闸门：一个数据集可用，当且仅当**存在**一个 δ 兑现这个标定
目标。没有引入新数字，也不能通过调它来放宽——调了就等于推翻 δ 的定义。

（补充理由，非选取依据：二值 label 上 95% 正确率 = 5% 标签噪声，是 BCE 训练可承受的
量级；低于此，比较器在拟合噪声。）

### 2.2 y_floor = 1/3 — 项目**已经接受过**的最低产量点

同一张探针判定表里，产量最低的**被判可用**的数据集是 Cricket：δ=0.08 时保留
**36.4%** 的配对，判定「高成本可用」。被剔除的 PenDigits 是 2.9% 保留 + 0% 正确。

y_floor = 1/3 ≈ 0.333 的含义是**「不低于项目已经接受的最差产量」**。这是一个
先例锚点：它在别的数据集上、别的会话里、为别的目的定下，与本次 13 个数据集的
结果无关。

（量纲核对，非选取依据：1/3 × 90 = 30 条 label/数据集/2 任务，对应阶段 2 全量
20 CLS × planned_tasks 的外推见 §4。同时它保证 A 的估计至少建立在 30 个配对上。）

### 2.3 没有第三个阈值

SNR 门槛**不进入 gate v2**。理由不是「它太严」，而是敏感性分析证明**它是惰性旋钮**：
从 1.0 降到 0.8 没有任何一个数据集翻盘（§4 结论 1）；它想防的「CLS 区分被噪声淹没」
已经被 A(δ) 直接测到了——PenDigits 式的数据集会在「任何 δ 都达不到 95%」上失败。
少一个旋钮就少一处可调空间。

## 3. 循环性怎么消除

### 3.1 用哪些 CLS 评估？——**仍用这 10 条，不剔除任何一条**

用户问：退化 CLS（如 `20be4f74`，info_nce+euclidean+τ=100，梯度信号退化到几乎不训练）
是否该从评估集剔除？

**结论：不剔除。** 理由：

1. **它在真实 CLS 空间里**。`configs/space.yaml` 把 τ=100 列为合法取值，搜索过程
   一定会遇到这类配置，比较器**必须**能给它排序。剔掉它等于假装空间里没有坏配置。
2. **阶段 2 一定会产出这些 label**：shared 10 = 探针目录前 10（`labels.yaml`
   `route_a` 段），这些配对下游照造不误。测「这个数据集会产出多少可靠 label」时
   把它们排除在外，反而与下游口径不一致——那正是旧判据的病。
3. **任何剔除规则我都写不出非循环的版本**：按本批数据的 |z| 定义（`probe_sensitivity`
   的做法）是从被评估的同一份数据里取的；按 HAR 排名定义已被证伪（§5.3：HAR 上最差的
   `8b87d66f` 在 UEA 上只是温和离群，HAR 次差的 `20be4f74` 才是极端离群）；按配置机制
   定义则划不清界（`8c4aa283` 同样 τ=0.01 却是 HAR 第 3 名）。

### 3.2 那循环性靠什么消除？——**靠判据对探针构成不敏感，且必须用数据证明**

不剔除 CLS，就必须证明新判据不再奖励「探针集里塞坏 CLS」。这是**实证问题，不是论证
问题**，本次必须给出的证据（阈值与判据已在上文写定，以下检验只报告、不回头改判据）：

| 检验 | 旧判据的值 | 新判据要看什么 |
|---|---|---|
| Pearson(子集中退化 CLS 占比, 任务数闸)，637 个子集 | **0.751** | 接近 0 才算消解 |
| 不含退化 CLS 的 93 个子集的任务数 | 最低 **44**（一个未实测源都不过） | 与含退化子集是否同量级 |
| 留一法 10 轮的判定翻转数 | 7/13 个数据集会翻 | 越少越好 |
| 任务数闸区间 | **[44, 108]**（±27%） | 区间宽度 |

**机制上的预期**（写在前面，好让数据有机会证伪它）：δ 过滤已经把近平局对移出分母，
而近平局对正是旧判据里被退化 CLS「稀释」的那批；A(δ) 的分母只剩本来就分得开的配对，
退化 CLS 贡献的平凡对与常规对在这个分母里都是 ~1.0，**加进来不改变比例**。
Y(δ) 会被抬高（退化 CLS 的对更容易过 δ），所以**产量指标仍可能有循环性残留**——
这一条必须如实测量并报告，不能假设。

### 3.3 附带诊断（不参与判定）

以下三项**不是闸门的一部分**，只作为诊断落盘，避免把「信息量」这种未经验证的新维度
偷偷塞进判据：

- **D1 平凡 label 占比**：存活 label 中涉及两条尾部 CLS 的比例。占比高 = 该数据集的
  label 多是「这条坏成这样的增强当然更差」，对学 **task-aware** 比较器信息量低
  （与记忆里 M3 路线 B「E 消融零下降」的观察同源）。
- **D2 任务特异性**：Spearman(该数据集上 10 条 CLS 的 R̄ 排名, 全 13 数据集合并的
  全局排名)。越接近 1，说明该数据集的偏好就是全局偏好，比较器无需看任务嵌入。
- **D3 注册表 δ 的兑现情况**：在 `labels.yaml` 当前 δ（10/13 是未实测的 N/C 阶梯推测值）
  下的 A 与 Y——回答「今天直接开阶段 2 会拿到什么」。

## 4. 任务数口径（与旧判据完全一致，便于对照）

沿用 `autocls/data/source_pool.py: task_count_gate`：
- 探针实测骨干 **44** = SpokenArabicDigits 16 + PhonemeSpectra 18 + Cricket 10，
  自动计入（`tested: true`；它们不在本批缓存里，无法也无需重评）；

- reserve（Ethanol / Heartbeat / FingerMovements）判 pass 也**不自动**进池，另列
  `reserve_bonus` 补充口径；

**一致性核对（非独立验证）**：把 gate v2 套回探针那 4 个数据集，应当复现探针自己的
判定——SpokenArabicDigits / PhonemeSpectra / Cricket 三个 pass、PenDigits fail
（其保留对 100% 是真平局、正确率 0%，任何 δ 都达不到 95%）。这只是自洽性检查，
不算独立验证：两个阈值本来就取自那张表。

## 5. 本判据自身的已知局限（写在前面）

1. **只覆盖 10 条 shared CLS**：阶段 2 每任务另有 10 条 random CLS 不在这批缓存里，
   Y 的绝对值不是最终产出量（跨数据集同口径，定性对比不受影响）。
2. **每数据集只有 2 个任务 × 90 个候选对**：A 的估计粒度很粗——n_kept=30 时
   「≥0.95」实际要求 29/30。会同时报告 Wilson 90% 下界作为诊断，但**判定用点估计**
   （与探针 §2.2 同口径；改用置信下界是一个新的、更严的决定，不在本次范围内）。
3. **探针 CLS 集合本身仍是那 10 条**：真正的解耦要从 `space.yaml` 重采一批常规 CLS
   重跑 R'（需要 GPU，不在本次范围）。本次只能证明判据对「这 10 条的子集」不敏感，
   这是不确定性的**下界**。
4. **δ\* 是在同一批数据上选的**：用同一批配对既选 δ 又报 A(δ\*)，A(δ\*) 因此乐观偏置。
   诊断上会补一个任务级留一（在 task 0 上选 δ、在 task 1 上报 A，反之亦然）来量化
   这个偏置。
