# 源池规模曲线报告：先验的 top-3 / SH 在 ≤2 个源即到地板，只有单默认（top-1）到 6–7 个源才稳定

协议 `PROTOCOL.md`（锁 a7cc81f）。脚本 `scripts/44_source_size_curve.py`，产物 `curve_rows.json / summary.json / tables.md`。
数据 `results/mx3_pq/rprime_cache.jsonl`（8 源，2700 行 shared + random；GGS 行不用），零 GPU，单跑 k=1。
7 折（SCP2 只训练），每折训练源 7 个，k=1..7 枚举全部子集（每折 127 个），共 889 个子集先验 × 该折 18 个实例（6 切片 × 3 预算）。

## 0. 一句话结论

按协议 §2 是**中间情况**：部署方法用到的那一层（先验前 6 + SH6-3-3、regret@3）在 k=2 就到了地板——regret@3 @290 对 k=1..7 全在 0.031–0.034，
SH6-3-3 @290 k=4 0.0231 vs k=7 0.0184（差 0.0047 < 0.005）；但**单默认的身份**到 k=6 才稳定（与全量 top-1 相同的子集比例 k=4 0.59、k=5 0.74、
k=6 0.88），regret@1 @290 从 0.082（k=1）一路降到 0.052（k=7），k=6→7 还降 0.010。原因不是平滑的学习曲线，而是顶部两条配置
（9092e36e vs cffb5503）的平局要靠全部 7 个源才分出来：去掉 Cricket / Handwriting / UWave 任一个，regret@1 平均升 0.023，去掉其他源为 0。
所以"加源提升精度"只对"单条学来的默认"成立，对"前 6 + 淘汰赛"这个部署方法不成立——它的 0.018 是数据集特异的不可约部分，加源填不上。

## 2. 补充读数

- **留一源（k=6 相对 k=7 的平均变化）**：regret@1 去掉 Cricket / Handwriting / UWave 各 +0.023，去掉 HMD +0.009，其余 0；regret@3 与 SH 的变化全部 ≤ 0.006（噪声内）。
  top-1 的竞争者只有 cffb5503（在 HMD 折 3/7 的 k=6 子集里胜出）。
- **最好的单源**（事后挑选，只作描述）：Cricket 靶用 SCP2 或 UWave 单源 SH 0.0042 vs 全量 0.0101；PhonemeSpectra 用 HMD 单源 0.019 vs 0.0233；
  Handwriting 用 UWave 单源 0.0013 = 全量 0.0013。单源就能到全量水平，说明 SH 那一层对源的选择不敏感。
- **子集间 sd**：k=2 0.0129 → k=6 0.0044（−66%），先验估计本身在收敛；收敛的是"估计"，不是"regret"。

## 4. 对"加源是否提升精度"的回答

- 提升的只有单默认的 regret@1（0.082 → 0.052），机制是解开顶部两条配置的平局；这与论文头条无关（头条是前 6 + SH）。
- 部署方法的 regret@3 / SH 在 2 个源之后再无可测的改善，且逐靶方向相反——这就是任务盲天花板的形状：先验越接近人群均值，离偏离人群的靶越远。
- 不能写"加源提升精度"；可以写"先验在 ≤4 个同域源上即收敛，瓶颈不在源的数量"。跨域（UCR）混入的读数本报告未算。

## 5. Limitations

- 单跑 k=1，regret 差 < 0.01 在噪声内；k=7 每折只 1 个子集（n=7）。
- 同一折内的子集彼此重叠，子集间 sd 不是独立样本的 sd。
- SCP2 只有 3 切片（自然半权）；"最好的单源"是事后挑选，无推断意义。
- 只有 7 个训练源，看不到 k>7；UCR 语料是不同口径（整数据集任务、T 截 512），没有并入。
