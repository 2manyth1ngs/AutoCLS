## 3. 诊断（事后，均标注为探索读数）

### 3.1 地板吞掉一半配置，且与增强强度无关

- 地板 = max(多数类, 3 个 iters = 0 探针均值)。探针（随机初始化 encoder + 官方 SVM）在 Cricket 切片上高达 **0.60–0.91**（12 类、评估 14–48 条），PhonemeSpectra 0.05–0.20（≈ 2 × 多数类），HMD ≈ 多数类 0.29–0.33（探针 0.16–0.33，四个任务是多数类作地板）。
- failed（best-of-3 ≤ 地板）份额：shared 0.45–0.66、random 0.52–0.54；**按 aug_max 分组 0.52–0.56 几乎相同**（random ≤ 0.5：0.53 / (0.5, 0.8]：0.55 / > 0.8：0.53；shared 同样）。所以不是"重增强破坏"，而是一半配置在"小切片 + 官方口径（batch 8、200/600 iters）"下训不过随机初始化的表示。shared-20 里 failed ≤ 8/24 任务的只有 2 条（f64cea8e 7、e3d73768 8），最差的 3 条（τ = 10 的 triplet 两条 + info_nce/euclidean/layer_norm）failed 17–18/24。
- 地板并列同时压低了保真度（早截点与终点大量并列）和相似度（画像里近半位置是常数）。

### 3.2 噪声：锚坐在地板边缘，跨种子在两侧翻转

- 锚 |Δ|（best-of-3 seed 0 vs 1，原始 acc）0.00–0.11；但 z 单位 MS_noise ≈ 1.0（HMD / PS）——两条锚（aug_max 0.80 的 8c482976、e3d73768）在 17/24 与 8/24 任务上 failed，跨种子在"地板 / 存活"两侧翻转，Δz 与整个配置分布同量级。协议 §1.4 的锚规则（shared 里按索引前两条 aug_max ≤ 0.8）选出的不是"稳定存活"的配置，噪声估计因此偏向最坏情形；这是协议设计的一个缺陷（事后发现，修订建议见 §5）。
- 按样本数档看（每集 2 任务 / 档）：failed 份额随 n 档单调下降（Cricket n0 0.79 → n3 0.38；PS n0 0.70 → n1–n3 0.34–0.47），n0 / n1 档的评估集 13–47 条（HMD 13–21）低于测量地板（acc 量子 2–8%，单跑 sd 0.035–0.048）。
- **事后只取 n 档 ≥ 2 的 4 任务 / 集重算 G-A2 量**：Cricket 0.802、PhonemeSpectra **0.582**、HMD −0.103——大 n 档 2/3 集过 0.5；HMD（4 类 EEG，acc 0.3–0.55，历史上无一致偏好）在任何 n 档都读不出结构。

## 5. 读法与下一步（待用户拍板）

1. **成立的部分**：三轴 OA 构造让同集任务不再共享一个偏好序（G-A1 从 0.77–0.90 降到 ≤ 0.34），这是 T-CLSC 历史上"E 学成数据集身份"的根因被拆掉的第一步；在评估集够大的档（n ≥ 2 档），Cricket / PS 的任务 × 配置交互超过种子噪声（0.80 / 0.58）。
2. **不成立的部分**：整体标签的信息量被两件事吃掉——样本数轴的低两档（评估 13–47 条）在测量地板之下；未训基线地板把 ~50% 配置并列在最末（与增强强度无关，是小切片 + 官方口径下的训练量问题）。相似度 0.10 / 0.03 说明现在的标签几乎没有可迁移的偏好结构，直接进 S2 / S3 只会把噪声喂给比较器。
3. **三条修订方向**（都需修订协议并重锁；估 3 集重跑 ≈ 3 h 墙钟，实验室机器零成本）：
   - (a) 抬样本数轴下限：n_lo = max(170, 5k)（评估集 ≥ 50 条；PS k = 39 → 195），四档仍取对数；本轮 n ≥ 2 档的 12 个任务可原样复用（key 不变）。
   - (b) 锚规则改为"seed-0 跑完后取 24 任务 failed 数最少的 2 条 shared 加 seed 1"（噪声估在存活区，而不是地板边缘）；只用于噪声估计，不进标签。
   - (c) 试点换掉 HMD（chance 级 4 类 EEG，任何档都读不出结构），改 UWaveGestureLibrary 或 Handwriting；HMD 留在 S2 只作训练侧。
   我的建议：(a) + (b) + (c) 一起做一次 S1′（≈ 1,000 格，服务器 3 h），G-A2 门不变；过门再铺 S2。不建议为救 G-A2 改地板定义（协议 §3.6-4 已锁）。
4. 与方案 §4 的关系：G-A 的"过门才铺全语料"照旧；S2 的 8 集 × 16 任务在 S1′ 之前不写代码。
