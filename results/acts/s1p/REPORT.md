## 3. 诊断（事后，均为探索读数；数字见 `diag_s1p.md`）

### 3.1 噪声修好了，S1 的 G-A1 "过门" 是噪声给的

- 两种子均值标签的噪声 MS_noise：PS 0.308 / Cricket 0.105 / UWave 0.124（S1 两锚估计 PS 1.03 / HMD 1.03 / Cricket 0.07）；存活配置跨种子 |Δacc| 均值每任务 0.004–0.031（S1 锚 best-of-3 0.00–0.11）；两种子都存活的 shared 每任务 0–13 条（PS 2–11、Cricket 0–11、UWave 8–13）。
- 对半分 ρ 由三部分决定：ρ ≈ V_cfg / (V_cfg + (V_int + V_noise) / 3)。S1 里 V_noise ≈ 1 把 ρ 压到 0.2–0.3；S1′ 噪声降到 0.1–0.3 后 ρ 回到 0.71–0.84。用 §3.2 的分解代入：Cricket 0.40 / (0.40 + 0.56/3) = 0.68（实测 0.706）、UWave 0.58 / (0.58 + 0.41/3) = 0.81（0.798）、PS 0.68 / (0.68 + 0.31/3) = 0.87（0.840）——三集都对得上。**结论：三轴 OA 构造并没有拆掉同集共同偏好，S1 只是没测出来。**

### 3.2 同集共同偏好序是真的，任务特异交互也是真的（两者并存）

| 数据集 | SS 任务 | SS 配置（集内主效应） | SS 交互 | 交互内噪声份额 | 对半分 ρ 协议 | 去掉共同失败块（≥ 6/8 任务 failed；剩余配置数） | 无地板原始 acc | 只算两半都存活的配置 |
|---|---:|---:|---:|---:|---:|---|---:|---:|
| PhonemeSpectra | 0.01 | 0.68 | 0.31 | 1.00 | 0.840 | 0.704 (9) | 0.935 | 0.606 |
| Cricket | 0.04 | 0.40 | 0.56 | 0.32 | 0.706 | 0.420 (11) | 0.860 | 0.605 |
| UWaveGestureLibrary | 0.01 | 0.58 | 0.41 | 0.34 | 0.798 | 0.724 (15) | 0.826 | 0.608 |

- 共同偏好序不是地板并列块造成的：去掉在 ≥ 6/8 任务都 failed 的配置后 ρ 仍 0.70 / 0.42 / 0.72；用不套地板的原始两种子均值 acc 反而更高（0.83–0.94，地板之下的配置也按同一集内序排）；只算两半都存活的配置 0.61（三集一样）。
- Cricket 的交互 SS（0.56）大于集内主效应（0.40）且真实份额 0.73——它是三集里任务分化最强的；UWave 主效应 0.58 / 交互 0.41（真实 0.72）；PS 交互 0.31 但噪声份额 1.00（真实 0.17，见 §3.4）。
- 按 n 档子集重算真实份额（每档 2 任务，只作方向）：Cricket 全部 0.73 / n ≥ 2 档 0.72 / n = 3 档 0.82；UWave 0.72 / 0.76 / 0.86；PS 0.17 / −0.42 / 0.68。抬 n_lo 之后 n 档已不决定份额（S1 里 n 档是主因）。

### 3.3 failed 仍吞掉一半配置（P6 ✗），与 n 档 / 增强无关、随温度单调

- failed 份额（shared + random）：按 n 档 0.48 / 0.51 / 0.52 / 0.53（n_lo 抬到 max(80, 7k) 没有改变它）；按 aug_max ≤ 0.5 / (0.5, 0.8] / > 0.8 = 0.50 / 0.47 / 0.52；按温度 τ 0.01 / 0.1 / 1 / 10 = **0.34 / 0.46 / 0.62 / 0.78**（只看 shared：0.38 / 0.51 / 0.65 / 0.85）；按几何家族最差 triplet/euclidean/l2 0.91、triplet/cosine/l2 0.70、info_nce/cosine/none 0.65，最好 info_nce/dot/none 0.23、triplet/dot/none 0.29。
- 与 S1 同集对照：failed shared PS 0.45 → 0.59、Cricket 0.56 → 0.65（终点标签不再 best-of-3 挑最大 + CV 探针地板更高：Cricket 探针 0.47–0.96、UWave 0.38–0.86、PS 0.10–0.15 ≈ 2–4 × 多数类）。BUD 消融已证明 3× 训练量不减 failed（0.60 → 0.66）：这些配置在"小切片 + 官方配方（batch 8、200 / 600 iters）"下训不过随机初始化，不是训练量问题。
- 相似度同集 0.50 / 异集 0.34 与 AutoCTS++ 的 0.75 / 0.40 同形（S1 的 0.10 / 0.03 是地板并列 + 噪声压出来的）。

### 3.4 PhonemeSpectra 在本口径下是 chance 型

## 5. 读法与下一步（待用户拍板）

1. **协议读数**：ACTS-S1P-SAME。G-A2 过门说明在干净标签下任务 × 配置交互超过种子噪声（Cricket / UWave 真实份额 ≈ 0.7），G-A1 不过说明同集任务同时共享一个强偏好序（集内配置主效应占画像方差 40–68%）。两条门在 S1 协议里被当成互斥的两种失败（"不分化" vs "分化是噪声"），实际数据是"既有共同序也有真实分化"——**G-A1 的对半分量测不出这个情形**（它把交互按 1/3 折算，只要共同序够强就 > 0.7）。这是协议设计的一个盲点，事后发现，如实记。
2. **与 AutoCTS++ 参照的关系**：AutoCTS++ 自己的语料同集相似度 0.75 / 异集 0.40（Table 4），本轮 0.50 / 0.34 与之同形；也就是说"同集任务共享偏好序"在 AutoCTS++ 那里本来就存在，它的 E 仍被报告为有效。所以 SAME 不等于"AutoCTS++ 式切片在本空间无效"，它等于"E 的可学对象 = 集内共同序（40–68%）+ 任务特异交互（31–56%，真实 ≈ 0.7）"，而项目历史上 E 塌缩成数据集身份对应的正是前者。S2 / S3 若铺，读数要针对后者设门（E 消融须在**去掉集内主效应后的残差**上可见），不能沿用 G-A1。
3. **语料质量的真正问题是 failed 0.51**：与 n 档、增强无关，随温度单调（τ = 10 的 shared 85% failed），几何家族 triplet/euclidean/l2 0.91；3× 训练量不救（BUD）；τ ≥ 10 全剪又不过 G-A0（21/29）。可选出路（都要重锁协议）：(a) 接受 0.5 的地板并列并把它当标签的一部分（AutoCTS++ 没有地板概念，它的 R′ 是连续的）；(b) 地板之下用原始 acc 保序（§3.2 显示地板之下的序也是同集一致的）——改的是标签定义，须先预注册；(c) 按 ADM 只用 UWave / HW / UniMiB / SCP1 这类地板较低、存活多的源铺 S2（源池 4 的 limitation 已记）。
4. **源池**：实测准入 4 < 7，Ethanol / SCP2 的发表数字先验（+0.06 / +0.08）与实测不一致，HMD / SCP1 一致；Cricket / PS 作为试点集但不作源（Cricket a07 全通道 × 最短窗 0 存活，PS a07 存活 7）。S2 的 8 集规划按协议不再补源。
5. 按协议 §2，只有 GO 才铺 S2；本轮不是 GO，S2 的代码与语料不写，等拍板。
