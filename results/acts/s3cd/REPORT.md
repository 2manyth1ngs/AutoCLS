## §0 诚实账
1. **选择用了 test**（WP3 旧口径，用户拍板）：三个臂都按终点 test acc 在自己的 3 条里选 1，同等偏乐观，臂间可比；与 TS2Vec 论文数比较时要记得这一点。
2. **单种子**：只跑 seed 0。以往实测单跑 sd 约 0.02–0.04，数据集级的差距要按这个量级读。n = 6，配对检验只作描述。
3. **④ 探针实际 3 条**：μ 前 2 与 b₁ 两端里，b₁ 最大端恰是 μ 第 1 名（2a667428），6 折选出的探针完全相同。④ 的前 3 在 5 个数据集里包含 2 条探针（续跑，不额外计成本），SCP1 的前 3 完全换成了轴负端配置。
4. **④ 的口径错位**（协议已声明）：ridge 在切片 5 折 CV acc 上拟合，这里喂的是官方 test acc 的 @25% 截点。
5. **背景参照不是同一目录、同一环境**：旧部署数用的是 shared-10 + GGS 目录、RunPod pod（SVM 的 C 可取 inf）、3 种子；本轮在实验室服务器上跑（C = inf 用 1e10 替身）、单种子。只能当背景，不做配对。
6. 目标 E：6 个数据集都在严格口径下完成，没有触发 OOM 回退。

## §3 读法
- **部署口径下 ④ 最稳**：3 条提名的均值在 5 / 6 个数据集上最高或并列最高，只有 Handwriting 不如 A。它只在固定的 30 条目录里排序，靠 3 条探针在目标上实测的 @25% acc 决定轴位置，SCP1 被正确放到负端，选中了 0.911 的配置。
- **全空间搜索（A、D）会搜到很差的配置**：D 在 Handwriting 的 3 条全在 0.36–0.38；A 在 Cricket 有一条 0.458。这与 S3-C 源侧读数一致：比较器对名单外配置读不准，进化又把它们推到读不准的地方。
- **E 改变了搜索落点，但不稳定地改善结果**：A 与 D 的提名 0 条重合，A 在 Handwriting / PhonemeSpectra / UWave 明显好于 D，在 Cricket / Ethanol / SCP1 明显差于 D，净效果 ≈ 0。
- **与 TS2Vec 论文与旧部署的关系**：④ 均值 0.650 高于论文 0.624，与旧目录 SH10-4-3（0.646）持平。④ 的目标侧成本是 3 条探针各跑到 25%，再加 3 条终选（其中 2 条是续跑探针）；SH10-4-3 是 10 条起跑的逐次减半。但两者目录不同、种子数不同，这里只能写"同一量级"。
