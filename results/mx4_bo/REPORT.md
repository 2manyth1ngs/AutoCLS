## 0. 一句话结论

读数码 **BO-DEAD**：在 WP3 官方口径 6 个 UEA 靶上，用靶侧 @25% 真值回灌、在信任域（汉明 ≤ 3）内迭代提名 3 轮 × 5 条，
**代理引导臂的提名 @100% 最大值只在 Ethanol 一个靶上超过目录 oracle + 0.01**（B1 1/6 ✗）；部署策略 BO-SH 的 3 种子均值
在 4/6 靶 ≥ 现行 SH6-3-3_prior，但六靶均值差 −0.011（HMD −0.153、PS −0.052 拖垮，B2 ✗）；代理引导的提名均值只在 3/6 靶
高于同成本随机邻域（B3 ✗）。HAR 描述性：BO-SH 选中与 SH6-3-3 相同的目录冠军 4f7d4135（3 种子 0.935 ≥ 线，P4 平凡命中）。
**目录之外确实有更好的配置，但它们几乎全在"@25% 看不出来"的地方**——回灌读的是早截点，早截点与终点的秩相关在池内只有
0.22–0.79，淘汰赛既不能稳定把提名留到终点，代理也只是在追 @25% 的赢家。开放空间搜索在本栈的唯一出口形态就此走完，判负。

## 4. 机制读法

1. **目录外有更好的配置，但只有 Ethanol 的够大**。7 靶里 5 靶的池 oracle 就是目录 oracle 或只高 0.003；Ethanol 两臂都找到了超目录的配置
   （bo cb76d4f9 = 父本 kernel 3→2、temperature 1→100，0.346；rand f2b1ebb1 = 第 2 轮提名再 crop 0.3→0.1，单跑 0.437、3 种子 **0.373**，
   高于 TS2Vec 论文 0.308 与 WP3 冠军 0.241）。HW 上 bo 第 1 轮找到 ee5e922e = GGS 改 order 2→4，0.549 与 GGS 0.546 同一水平——
   开放空间在 GGS 邻域内没有更高的点。
2. **回灌信号是瓶颈，不是代理**。池内 @25% 与 @100% 的 Spearman：HMD 0.22、Ethanol 0.31、HW/PS/Cricket 0.60、UWave 0.79、HAR 0.78。
   淘汰赛按 @25% 留 3 条：HW 上 @25% 前 3 的 @100% 是 0.453/0.478/0.478，而池内 @100% 前 3 是 0.549/0.546/0.545（全部被第一级淘汰）；
   PS 上目录冠军 4f7d4135（@25% 0.238）被 20 条提名（@25% 0.24–0.25）挤出，BO-SH 从 0.251 跌到 0.220；HMD 上 @25% 前 3 的 @100% 只有 0.23–0.28。
   这就是 WP5 的判死（早截点外推淘汰不可用）在"起跑名单变大"时的放大形态：名单越大，@25% 的赢家诅咒越重。
3. **代理引导有方向但不可靠**。bo 提名均值在 HW（+0.100）、HAR（+0.027）、UWave（+0.018）高于随机邻域，在 PS/EC/Cricket 略低；
   bo 提名内 pred_z 与 @100% 的 Spearman 在 −0.36 到 +0.29 之间无信号。回灌后代理的预测 z 从第 1 轮 0.9–1.4 跳到第 2 轮 2.1–2.5（HW/HMD）：
   靶侧 @25% 领先者的 z 行（×10 权重）让模型把"@25% 领先者的 1 字段近邻"全部标成极高分（第 2 轮汉明几乎全 1）——代理在忠实地追 @25%，
   而 @25% 不是目标。Ethanol 的 0.437 由随机臂找到（pred_z −0.01），代理臂在同一父本集上第 3 轮均值反而跌到 0.275。
4. **父本停滞**。Ethanol 和 HMD 的 bo 臂第 2、3 轮父本完全相同（新提名的 @25% 没有一条进前 5），第 3 轮只是换 seed 在同一邻域再抽——
   3 轮里有效的探索只有 2 轮。随机臂因为父本随机进入反而在 Ethanol 第 3 轮跳到 0.344 均值。
5. **HW 的 TS2Vec 线**。BO-SH 冠军 4efaf3b1（目录外，e490b88e 的近邻）3 种子 0.497 ≥ 0.485，是本栈第一次在 HW 官方口径上过 TS2Vec 线；
   但同靶 SH10-4-3（5.0 全跑当量）拿到 GGS 0.546，BO-SH 花 7.5 只到 0.497——WP3 记的"HW 是名单失败"仍然成立，最便宜的修法是起跑名单到 10。
6. **成本**。BO-SH / RAND-SH 7.5 全跑当量 = SH6-3-3 的 2×；缓存墙钟 BO-SH 1.5–5.5× SH6-3-3（EC 1240 s vs 226 s，提名格比目录格慢），
   且目录格是 4090 秒、提名格是 4060 秒，墙钟比偏向高估 BO——iters 当量才是干净口径。

## 5. Limitations

- 提名 seed 0 单跑（k=1，sd 0.035–0.048），B1 的 +0.01 边际在噪声内；只有冠军补了 3 种子。B1 单独通过与否本来就不是决定性读数（协议已写）。
- 3 轮 × 5 条、κ=1、半径 3、父本 5 全部固定未调（协议 §6）；回灌只用 @25%——用 @50% 回灌会把每条提名的成本翻倍，未做。
- PS 1 格超时（error）使 BO-SH 起跑 20 条、成本 7.25；Windows 上限是运行中补的（§7），前 160 格没有上限但也没有触发。
- Cricket 贴顶（1.000）、HAR 目录 oracle 已在先验前 4——两靶对 B1/B3 无判定力。
- 墙钟成本混合 4090（目录）与 4060（提名）两种硬件；只报 iters 当量作结论。
- 冠军 3 种子复用 WP3 的终评行（同 cls_key），与本包新跑的 seed 1/2 混在同一均值里；两者同协议同代码，GPU 非确定性量级 ±0.005。

## 6. 教训（运维）

- Windows 无 SIGALRM 时 39 号的 480 s 评估上限静默失效，PS 退化格空转 82 min；已用 loky 子进程版补齐（`eval_with_timeout_win`，2 单测）。
  以后凡在 Windows 跑 39/43 号，启动日志必须出现 "Windows：截点评估上限 …" 这一行。
- `Add-Content` 往被 `tail -F` 打开的日志追加会失败（stage 标记丢失，进程不受影响）；标记应写到单独文件或用 `cmd >>`。
- 脱离进程 + `--resume` + 一体化 run_all 脚本这次工作正常（重启一次即接续）。

## 7. 后续与论文写法

- **第三条关闭**：开放空间搜索的唯一合法形态（信任域提名 + 目标侧真评估回灌）在官方口径 6 靶上没有通过任何一个门。
  论文里"搜索"只写目录内的零样本排名 + SH；limitations 引本报告 §4.2（回灌信号 = 早截点，是 WP5 判死的同一地板）。
- 两个可写进 analysis 的正面事实：(i) Ethanol 目录外存在 0.373（3 种子）的配置，高于 TS2Vec 论文与目录 oracle——目录不是空间的天花板；
  (ii) HW 上 BO-SH 3 种子 0.497 过 TS2Vec 线但不及目录内 GGS 0.546——HW 的问题是起跑名单，不是空间。
- 不再立项：调 κ / 半径 / 轮数、改回灌截点到 @50%、把提名与代理分混排——前两者在 §4.2 的地板上没有理由更好，第三者阶段 0 已判负（MIX-SH）。
